always look for the FIRST error!!

printf prints inline. do println for newline, or add \n inside the string

"auto" when declaring a variable makes a copy of whatever it's referencing. to directly reference the object, do "auto&"

.h files are the menu, they tell you what exists (verbs, function declaration etc)
.cpp files are the kitchen, they determine what is INSIDE the functions etc.

so main.cpp will use my abstracted, platform-agnostic verbs, which are defined in input.h, and the input_core2.cpp for the core2 version of the game will "hear" the calls for the verbs and respond with the core2 button inputs and what they should do

static means "private to this file"

for includes, angle brackets mean libraries and quotes mean "one of my files" - the path starts from /src/

`void` a function that just does something without returning a value to whatever called it. as opposed to `bool` or `int`

`#pragma once` means the file only gets read once, even if it gets included twice

On Characters, Strings, and Variables:

`const char` means "text that won't be changed". so c++'s "string" is `const char*`

but a formatted string would be `const char* fmt, ...` - fmt meaning format, and "..." being "and whatever else"

when using ingame variables:
- use %d for int
- %f for decimals, %.2f for 2 places
- %s for a string
- %% for a literal "%" sign

Reading errors:
- "X does not name a type" = wrong name or wrong namespace prefix (m5:: vs none etc). try dropping/changing the prefix
- "no matching function for call to X(Y)" = X exists but doesn't take a Y. scroll down for the "note: candidate:" lines, they list what it DOES take
- "did you mean ...?" = the compiler is usually right, check for typos

& before a thing (variable or object) means "the address of this thing." & after a type (which is NOT a thing) means "a reference to this thing"

"int& w" is a reference parameter. It allows the function to write into the caller's variables so it can return success/failure, plus W and H. (example in display_core2.cpp)

- be careful you don't accidentally do $ instead of &

this isn't to be confused with *, which when added after a TYPE, means "the address of an instance of this type" (ie Scene* = the address of a Scene)

"->" is a dot for pointers, it lets you call the proceeding function on whatever it's pointed at (from?) (ie current_scene->update() calls update() on current_scene)

- be careful you don't accidentally do => instead of ->

"nullptr" points at nothing. you always need to check for nullptr BEFORE you use "->" or else things can crash
